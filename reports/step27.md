# Step 27 report: public mode demo fixes

Branch `step27-public-fix`.

## What was wrong
1. The UI defaulted to mock mode unless the URL had `?mode=api`, so a plain URL played canned screens (including the fixed "too blurry" error, job `job_pub_0002`) and the ExampleMed sample.
2. The public scan job rejected a clean image as `low_contrast` (p95 minus p5 gray levels reads a mostly white pack with sparse text as flat: contrast 37 against the cut-off 40, sharpness 1528).
3. The photo scan reader needs the Tesseract program. It was installed at `C:\Program Files\Tesseract-OCR` but not on PATH, so every real scan ended in `scan_failed`.
4. P2 and P3 showed the sample ExampleMed screens in api mode when no live answer existed.
5. Typing an unmatched name (Advil) on P3 ended in a bare error with no way to the live DailyMed lookup.

## Changes
- `ui/js/data.js`: default mode is api, `?mode=mock` selects the static mocks.
- `ui/js/public-app.js`: opens on the scan tab, nav clicks always re-render, api mode (outside the `?dev=1` panel) replaces a mock stand-in on P2 with "No label loaded for this name" plus Search DailyMed and shows an empty question box on P3.
- `ui/js/render-p3.js`, `ui/js/live-dailymed.js`: an unmatched name shows "No label loaded for this name" with the existing live search (`LabelLensLive.mountSearch`); after the label is fetched, Ask answers from it with citations.
- `scripts/run_demo.py`: `ensure_tesseract()` adds a standard Windows folder to PATH and prints one startup line.
- `src/api/public_scans.py`: a photo whose only gate reason is `low_contrast` and whose sharpness is at least 400 is read. Blur, glare, and low contrast on a soft photo still reject. A photo never auto-confirms.
- `.gitignore`: `golden/` (generated by `ui/tools/golden_setup.py`).
- UI tools: `check_screens.cjs` passes `mode=mock` explicitly, `live_check.cjs` waits for the scan tab, new `nolabel_check.cjs`.

## Frozen numbers
The quality-gate change is in the job code of `public_scans.py` only. `src/api/quality.py` and its thresholds are untouched. The NDC scan, public scan and live DailyMed evaluations do not call that job: `scripts/public_scan/evaluate.py` calls `assess_photo` directly, and the NDC and live scripts do not use the gate. No frozen number is changed and nothing was re-run. One caveat: the public scan report has a "pipeline view" that counts a gate-rejected photo as retake; for a photo whose only reason is low contrast with sharpness 400 or more, the live job now reads it instead, so that view no longer describes the job exactly for those photos.
